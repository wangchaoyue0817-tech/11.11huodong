# 图灵鉴 X · 鉴定与抽奖独立工程

从统一体验工程提取的可运行前端，仅包含首页 AI 鉴别、首页专家鉴别、卡牌鉴定、抽奖中心及关联弹窗。专家首页按提供的参考图调整了布局与文案，原有专家选择流程完整保留。

## 本地运行

需要 Node.js 22 或以上，无需安装第三方依赖。

```bash
npm run dev -- --host 127.0.0.1 --port 4181
```

打开 `http://127.0.0.1:4181/`。也可直接执行：

```bash
node scripts/serve.mjs --host 127.0.0.1 --port 4181
```

验证与构建：

```bash
npm test
npm run build
npm run preview -- --host 127.0.0.1 --port 4182
```

构建结果位于 `dist/`，可部署到静态服务器。所有图片、图标、样式与脚本均在本项目内，无外部 CDN 或旧预览站依赖。需要通过 HTTP 打开，不支持直接双击 HTML 的 `file://` 模式。

## 保留范围

| 入口 | 保留的内容与交互 |
| --- | --- |
| `/#home` | AI 技能轮播、推荐 Banner、话题、技能选择、图片本地预览、文本咨询演示；图片识别为卡牌的演示结果与新人礼入口 |
| `/#expert` | 参考图首页、立即鉴别、28 个鉴定品类、品牌/系列和款式搜索、品类切换、选择状态、服务协议、缺失产品反馈、确认选择、返回与关闭 |
| `/#card` | 卡牌动效、上传/样例、品牌与款式选择、AI 结果、专家复核与支付/用券模拟、获券弹窗、活动入口 |
| `/#lottery` | 新人五连抽、普通单抽/五连抽、同时翻牌、跳过动画、取消/关闭保护、获券记录、用券记录、未使用/已使用/已过期状态、邀请与满额转发演示 |
| `/#prizes` | 每批抽奖结果、专家鉴定券、实物奖品、收货信息填写与修改 |

各模块由同一站点内的路由壳承载，不跳转到原预览地址。两个独立页面容器隔离既有样式；页面切换不会重建已加载模块。新建对话返回首页并清理当前对话，不会清空抽奖权益与历史。

已移除鉴皮肤、皮肤报告、皮肤管理、商品订单、穿搭/鉴餐管理、虚构侧栏历史及对应构建依赖；保留首页 AI 技能入口和专家产品库内原有的美妆等商品鉴别品类，它们不是皮肤检测功能。

## 专家鉴别交互说明

点击“立即鉴别”后，完整保留原工程的：

1. 选择品类；品类列表的滚动位置保留。
2. 搜索、选择品牌/系列，再搜索、选择款式；可切换品类、返回重选。
3. 查看协议，未勾选时确认会提示补充。
4. 未找到产品时可填写反馈并在本次演示中保存。
5. 确认后显示已确认状态；关闭并再次打开仍保留本次选择。

原工程的这个专家首页流程止于“确认选择”，没有真实订单、点位照片上传、后端支付或鉴定结果接口。本次没有删减这些既有交互，也没有把未实现的服务伪装成已接通。

## 重要边界

- 这是 HTML/CSS/JavaScript Web 前端，不是微信小程序原生工程。小程序上线需要迁移页面组件并接入微信能力。
- AI 识别、专家支付、发券、抽奖、领奖、转发均为本地模拟；不上传真实图片、不扣款、不发放真实奖品。
- 首页未指定其他技能时上传图片，会进入“识别到卡牌”的固定演示，不是图像识别模型。
- “去使用”保留交互反馈，不接入真实鉴定券核销。
- 邀请方式统一表达为转发小程序，没有邀请链接；浏览器中仅模拟邀请和奖励状态。
- 专家首页中的“错一赔三”“最快30分钟”“6亿+”为用户参考图文案，不代表本代码已验证或提供相关服务承诺。
- 活动日期与概率沿用原提取版本，默认使用 **2026-09-25 起的演示时钟**；仓库名不表示日期已改为双十一。真实运营规则请在 `public/lottery-model.js` 中配置并对接服务端。
- 本地演示状态保存于当前域名的 `localStorage`，键为 `jianx-card-preview-v1`。可通过“演示模式 / 切换演示场景”测试不同状态；切换场景会替换当前域名的演示记录。
